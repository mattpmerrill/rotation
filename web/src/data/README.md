# data

Repositories, the only place a database query is built. Server-only: every file that touches Supabase or a secret starts with `import "server-only"`.

- `<thing>.repository.ts`: one per table or concern (`entries`, `trades`, `prices`, `people`, `auth`, ...). Reads throw on failure, because a failed read is unexpected; writes return an `ApplicationResult` with the failure translated by `failure.ts`, so no database text reaches a user.
- `*.repository.ts` for the files the engine writes (`history`, `timing`, `reference`): parsed with a Zod schema when the server starts, so a change on the Python side fails loudly.
- Plumbing with no business meaning: `env.ts` (the one place `process.env` is read and validated), `supabase/` (the clients), `failure.ts`, `origin.ts`, and `guards.ts` (the access checks every Server Action starts with).
- `database.types.ts` is generated by `npm run db:types`; never edit it.

May import: `domain` and `lib`. Not `integrations`: when a repository needs something from a vendor, the feature passes the call in (`loadCurrentChallenge` takes a `liveQuotes` function).

Example, `snapshot.repository.ts`: loads a challenge's entries, trades and prices through the other repositories, and returns one `ChallengeSnapshot` for the leaderboard, the entry page and the daily job.
