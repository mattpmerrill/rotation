# Exceptions

Rules from the engineering standards this repo follows ([ADR-001](decisions/ADR-001-adopt-engineering-standards.md))
that it does not meet yet, or does not meet on purpose. Each has a reason, a scope and an
expiry. Reaching an expiry means fixing it or re-recording it here with a new date and a stated
reason. A one-off exception for a single commit goes in that commit as an
`Exception: <rule> - <why> - expires <YYYY-MM-DD>` trailer instead.

The approver, for now, is Matt. Measured counts were re-measured on 2026-09-30 and are in
[enforcement-matrix.md](enforcement-matrix.md).

| # | Rule | Why it is not met | Scope | Expires |
|---|---|---|---|---|
| 3 | Structured logs, correlation ID, alerts (the observability standard) | `lib/log.ts` writes one JSON line per event and `dbFailure` and `authFailure` log with codes, but no correlation ID is carried through a request and no alert channel hears about a failed daily job or an unexpected error. | whole web app, daily job | 2026-10-31 |
| 7 | Money is never floating point (the data standard) | The domain layer computes BTC in JavaScript floats. Decided: integer sats ([ADR-003](decisions/ADR-003-btc-quantities-as-integer-sats.md)). | `web/src/domain`, `data/entries.repository.ts` | 2026-10-31 |
| 8 | Frontend kit: one headless primitive library, a `/design` page with a census test, component tests, all four states verified, reduced-motion honoured (the frontend standard) | Not built yet: the interface is hand-made from tokens. Until then ESLint refuses new literal colours, radii, shadows and z-indexes, with 11 files that already had them on a list that can only shrink (`eslint.config.mjs`). | `web/src/ui`, `web/src/features/*/components` | 2026-11-15 |
| 9 | Signed-in end-to-end journeys and accessibility checks on signed-in pages (the testing standard) | Sign-up, approval, help links and rejection now have a signed-in journey against the local Supabase (`e2e/signed-in`, in CI). | 11 | Documented RPO and RTO, a backup that meets them, a tested restore (the operations standard) | The Supabase project is on the free plan and nothing backs up members' trades. Market data can be rebuilt by the engine; trades and baskets cannot. Next step: a scheduled dump of the user tables. | production database | 2026-10-31 |
| 12 | No production system with availability requirements on a pausable tier (the operations standard) | The system has no availability requirement (best effort, see [system-context.md](system-context.md)), and the daily job's traffic keeps a free project from pausing for inactivity. | 14 | Preview-environment smoke test (the engineering standards) | Trunk is production, so there is no pull request and no preview URL to test. | 16 | Dead configuration and data removed with the feature (the deprecation standard) | Partly done. Still open: the 17 `rules.yaml` sections (removing them needs a `rules.yaml` version bump and a changelog line, which the owner schedules) and the two tables. Each is its own change ([ADR-004](decisions/ADR-004-archive-cycle-harvest-engine.md)). | `config/rules.yaml`, `engine/.../config.py`, Supabase | 2026-10-31 |
| 17 | Verify the email address, and offer a password-reset flow (the security standard, ASVS L2) | Supabase's built-in email sender only delivers to the organization's own team, so with no email service confirmation and reset emails cannot work ([ADR-006](decisions/ADR-006-signup-and-approval.md)). Fix: a custom SMTP provider, then turn confirmation on (the app handles both). | Supabase Auth, `features/auth` | 2026-12-31 |

## Retired

Fixed exceptions stay listed so the numbers other docs refer to keep meaning something.

| # | Rule | Fixed |
|---|---|---|
| 1 | Handler, service, repository chain | 2026-09-28. `trades`, `picker`, `auth` and `admin` each have a service and thin actions, and every action goes through a service (checked by grep; no tool enforces it, see the matrix). |
| 2 | Typed result, stable error codes, no database or Auth text shown to users | 2026-09-28. Every feature returns `ApplicationResult`; `dbFailure` and `authFailure` translate and log, and no raw `error.message` reaches a user. |
| 4 | Runtime validation at every trust boundary (the security standard) | 2026-09-30. CoinGecko's response is parsed with a zod schema in `web/src/integrations/coingecko/live-prices.ts` (a malformed quote is skipped, a malformed body gives `null`; tests in `live-prices.test.ts`), and the engine's three JSON files are parsed with schemas when the server starts (`data/history.repository.ts`, `timing.repository.ts`, `reference.repository.ts`; `data/engine-files.test.ts` parses the committed files). Forms, params, request bodies and env were already parsed. Found by reading every boundary; no tool flags a new one, so it stays a review item. |
| 5 | Unsafe type assertions carry a documented boundary reason (the TypeScript standard) | 2026-09-30. The 40 unexplained `as` casts are gone or explained: non-test code in `web/src` has 4 left, each with a comment naming the boundary (two CSS custom properties in `ui/bitcoin-spinner.tsx`, two Recharts tooltip payloads). Found by grep; not detectable by a linter, so it stays a review item. |
| 6 | Files and folders are `kebab-case` | 2026-09-28. All 42 legacy names renamed and the guard's exemption list is empty (`scripts/guards/filenames.exempt.json`), so any new violation fails the check. |
| 10 | CSP and standard security headers (the security standard) | 2026-09-30. `src/proxy.ts` sets a nonce-based Content-Security-Policy per request; `next.config.ts` sets `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options: DENY`, `Strict-Transport-Security` and `Permissions-Policy` and turns off `X-Powered-By`. `e2e/security-headers.spec.ts` asserts them and the browser suite passes (38 signed-out runs, re-run 2026-09-30). |
| 18 | A deterministic `seed.sql` exists (the data standard) | 2026-09-30. `supabase/seed.sql` (about 600 KB, generated by `supabase/seed/build_seed.py` from the engine's cached public prices; the same input gives the same bytes) loads on every `supabase db reset`. It holds invented people, and the pgTAP suite still passes (74 tests) on the seeded database. |
